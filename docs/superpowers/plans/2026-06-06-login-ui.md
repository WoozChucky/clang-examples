# Login UI Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gate the dual-server connection behind UI — a **Start Game** button opens a **login** screen (real text entry); submit drives a **Connecting** screen while the existing auth→world→char flow runs; reaching in-game enters the level; a failure returns to login with an error.

**Architecture:** Pure `Game.dll` (builds on the merged engine/game boundary + game-component reload-safety). Game-owned `Login`/`Connecting` states; a `LoginForm` game singleton; login UI seeded as `StateScope`-gated entities; fields are `MenuButton`s (so the existing `MenuInteractionSystem` gives click→focus + hover for free, and they're identified by a built-in `ActionId` that survives reload); a new `LoginUISystem` owns text entry; `AppFlowSystem` owns state transitions; `ClientSessionSystem` is gated on `Connecting` and reads the typed creds.

**Tech Stack:** C++23, MSVC (`msvc-win64-vs2026-community`), CMake. Touches only `src/game/` + `src/game/include/GameStates.h` + a new test. No engine/`ecs.dll`/common edit; no `GAME_API_VERSION` bump (`LoginForm` is an ECS singleton, not a `GameState` field).

**Scope:** Implements `docs/superpowers/specs/2026-06-06-login-ui-design.md`. Prerequisite `game-component hot-reload safety` is merged. Out of scope: world/char selection screens (auto-advance stays), real auth, caret, live per-step status.

#pragma once
#include <string>
#include "input.h"

// Apply one raw input event to a text field: append a printable TextInput codepoint
// (ASCII range; >= 32 and < 127), ignore everything else. Backspace/Enter/Tab are NOT
// handled here — the caller reads those from InputStateComponent.Pressed. Pure + testable.
inline void ApplyTextEdit(std::string& field, const InputEvent& ev) {
    if (ev.Type != InputEventType::TextInput) return;
    const uint32_t cp = ev.TextEvent.Key;
    if (cp >= 32 && cp < 127) field.push_back(static_cast<char>(cp));
}

### Task 3: `LoginUISystem` + `AppFlowSystem` transitions

**Files:**
- Modify: `src/game/src/game.cpp`

- [ ] **Step 1: Add `LoginUISystem`**

Add a system (Simulation phase). It must run **after** `MenuInteractionSystem` (so the field-focus actions it consumes are already in the queue this tick) and **before** `AppFlowSystem`. Place it in `game.cpp` near the other UI systems:
```cpp
class LoginUISystem final : public ISystem {
public:
    SystemPhase Phase() const override { return SystemPhase::Simulation; }
    void Update(SystemContext& ctx) override {
        const auto* gs = ctx.world.GetSingleton<GameStateComponent>();
        if (!gs || gs->Current != StateIndex(GameStateId::Login)) return;

        // Seed-if-absent (survives the reload barrier clearing it).
        if (!ctx.world.GetSingleton<LoginForm>()) ctx.world.SetSingleton(LoginForm{});

        // 1) Focus changes: MenuInteractionSystem fired a field's focus action this tick.
        if (const auto* q = ctx.world.GetSingleton<ActionQueueComponent>()) {
            for (const ActionEvent& e : q->Events) {
                if (e.ActionId == loginui::kFocusUsername)
                    ctx.world.ModifySingleton<LoginForm>([](LoginForm& f){ f.Focused = LoginField::Username; });
                else if (e.ActionId == loginui::kFocusPassword)
                    ctx.world.ModifySingleton<LoginForm>([](LoginForm& f){ f.Focused = LoginField::Password; });
            }
        }
        const auto* in = ctx.world.GetSingleton<InputStateComponent>();
        if (in && in->Pressed[KEY_TAB]) {
            ctx.world.ModifySingleton<LoginForm>([](LoginForm& f){
                f.Focused = (f.Focused == LoginField::Username) ? LoginField::Password : LoginField::Username;
            });
        }

        // 2) Typing into the focused field (from this tick's raw events) + backspace.
        ctx.world.ModifySingleton<LoginForm>([&](LoginForm& f){
            if (f.Focused == LoginField::None) return;
            std::string& field = (f.Focused == LoginField::Username) ? f.Username : f.Password;
            for (std::size_t i = 0; i < g_GameState->FrameInputEventCount; ++i)
                ApplyTextEdit(field, g_GameState->FrameInputEvents[i]);
            if (in && in->Pressed[KEY_BACKSPACE] && !field.empty()) field.pop_back();
            if (!field.empty()) f.Error.clear(); // typing clears a prior error
        });

        // 3) Submit handling (Enter OR the Submit button) with empty-username validation.
        //    The Submit MenuButton fires kSubmitLogin into the queue via MenuInteractionSystem;
        //    Enter is an alternative trigger. We validate here and only let a VALID submit reach
        //    AppFlowSystem (which turns kSubmitLogin -> Connecting). Invalid → set error + strip.
        {
            const bool enter = in && in->Pressed[KEY_ENTER];
            bool queued = false;
            if (const auto* q = ctx.world.GetSingleton<ActionQueueComponent>())
                for (const ActionEvent& e : q->Events) if (e.ActionId == loginui::kSubmitLogin) queued = true;
            if (enter || queued) {
                const auto* f2 = ctx.world.GetSingleton<LoginForm>();
                const bool ok = f2 && !f2->Username.empty();
                if (!ok) {
                    ctx.world.ModifySingleton<LoginForm>([](LoginForm& f){ f.Error = "Username required"; });
                    ctx.world.ModifySingleton<ActionQueueComponent>([](ActionQueueComponent& q){
                        q.Events.erase(std::remove_if(q.Events.begin(), q.Events.end(),
                            [](const ActionEvent& e){ return e.ActionId == loginui::kSubmitLogin; }), q.Events.end());
                    });
                } else if (enter && !queued) {
                    ctx.world.ModifySingleton<ActionQueueComponent>([](ActionQueueComponent& q){
                        q.Events.push_back(ActionEvent{ loginui::kSubmitLogin, 0, 0 });
                    });
                }
                // valid + button case: leave the queued kSubmitLogin for AppFlowSystem.
            }
        }

        // 4) Mirror state → field display text (+ focus highlight) every tick.
        const auto* form = ctx.world.GetSingleton<LoginForm>();
        if (!form) return;
        ctx.world.Each<MenuButtonComponent, TextComponent, UIRectComponent>([&](EntityId e) {
            const auto* mb = ctx.world.GetComponent<MenuButtonComponent>(e);
            if (!mb) return;
            const bool isUser = mb->ActionId == loginui::kFocusUsername;
            const bool isPass = mb->ActionId == loginui::kFocusPassword;
            if (!isUser && !isPass) return;
            const std::string shown = isUser ? form->Username : std::string(form->Password.size(), '*');
            ctx.world.Modify<TextComponent>(e, [&](TextComponent& t){ t.Text = shown; });
            const bool focused = (isUser && form->Focused == LoginField::Username) ||
                                 (isPass && form->Focused == LoginField::Password);
            if (focused) ctx.world.Modify<UIRectComponent>(e, [](UIRectComponent& r){ r.Color = glm::vec4{0.30f,0.30f,0.40f,1.f}; });
        });
        // Error line: find the red error text entity by scope is awkward; simplest — store its
        // text via a dedicated marker is avoided. Instead mirror Error onto ALL Login-scoped
        // TextComponents tagged as error? Simpler: skip a dedicated error entity lookup and
        // render the error as the window title suffix is not possible. SEE NOTE below.
    }
};
```
**NOTE on the error line:** the seeded error `TextComponent` entity has no `MenuButton`, so the `Each<MenuButtonComponent,...>` loop won't touch it. To update it, give the error entity a distinguishing built-in marker: seed it with a `MenuButtonComponent{.ActionId = kErrorLine}` (a 4th game-local action id, never fired — fields/buttons already use MenuButton; an unfired ActionId is inert in `MenuInteractionSystem` because release-inside fires it, but the error line is non-interactive text over no rect... it would have no `UIRectComponent`, so `MenuInteractionSystem`'s `Each<MenuButtonComponent,UIRectComponent,TransformComponent>` skips it — safe). Then in `LoginUISystem`, a second `Each<MenuButtonComponent,TextComponent>` finds `ActionId == kErrorLine` and sets `t.Text = form->Error`. Add `constexpr uint32_t kErrorLine = MakeAction(ActionCategory::Nav, 23);` to the `loginui` namespace, seed the error text entity with `MenuButtonComponent{.ActionId=loginui::kErrorLine}` (Task 2 Step 3), and add the error-mirror loop here. (This keeps identification built-in + reload-safe, consistent with the fields.)

(Submit + empty-username validation is handled in the LoginUISystem block above — section (3). Needs `#include <algorithm>` in `game.cpp` for `std::remove_if` if not already present. The invariant the reviewer checks: an empty username never reaches `Connecting` (the `kSubmitLogin` is stripped), and a valid submit yields exactly one `kSubmitLogin` for `AppFlowSystem`.)
